\section{Conclusion}
Paid finite-catalog renewal design admits exact selected-boundary resource and price representations under its original expected and realized constraints. History-level component packing extends the primal identity to heterogeneous rewards. The representations separate model-specific structure from established resource allocation, Lagrangian bounding and discrete search mechanisms.

The cap-count theorem identifies a tight small-menu structure: twice the number of distinct expected caps is both sufficient and sometimes necessary under a common reward. The deficit coordinate makes the terminal resource state independent of the anchor, removes a catalog factor from the primal approximation, and supports an exact zero-service lattice algorithm at arbitrary command budgets. These results complement, rather than replace, the common-cap and common-prefix exact subclasses, the weak encoding-sensitive hardness construction, safe catalog rules and robust capacity-repair arguments.

The computational records distinguish the costs of optimization, proof representation and independent checking. A positive-tolerance price bound may stop at the root; exact-target trajectories reveal when branching is actually needed. The heterogeneous deficit implementation supplies a polynomial alternative, but its explicit checker can cost substantially more than optimization. Screening can improve a bound or reduce the book universe without improving total proof time. These distinctions identify which structural result is useful for a given instance instead of treating one completion label as a general performance claim.

The service-credit architecture supplies an implementation and calibration interface, not a claim of field validation. Fixed feasibility controls and estimated payoff primitives play different roles. Keeping them separate permits original-instance certificates and explicit payoff-error transfers to inform operational decisions without altering the accepted obligation.

The accompanying code and data retain the complete predecessor source and evidence package and provide the current heterogeneous deficit optimizer, lattice mode, exact price search, book enumeration, numerical mixed-integer comparison, independent checkers, input records, full trajectories, and every declared failure. Current and antecedent execution records have separate protocols and source hashes. A post-inspection exact-target study and a separate extended-verification pass are explicitly identified. Compressed certificates include the requested model; external instance hashes bind verification to that model. Reproduction instructions, the reader map, provenance, and build validation are supplied with the package. Repository transport and formatting checks are not scientific contributions or editorial acceptance decisions.

Approximate reward types provide a certified tradeoff between menu size and value without perturbing feasibility. Saturation provides a separate exact all-budget regime with positive service costs. Together these results show why the useful structural parameters are not interchangeable with numerical precision or command count alone.
